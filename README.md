# IEEE-CIS Fraud Detection

ამ კონკურსის მთავარი მიზანი იყო დიდი დატასეტიდან ისეთი მოდელის გაწვრთნა, რომელიც განსაზღვრავდა ტრანზაქცია ყალბია თუ არა. ეს არის კლასიფიკაციის ამოცანა, რომლის გადასაჭრელად ვცადე რამდენიმე სხვადასხვა მიდგომა: Logistic Regression, Decision Tree, Random Forest და XGBoost.

## ექსპერიმენტები

- `model-experiment-logistic` — Logistic Regression-ის ტრენინგი
- `model-experiment-decision-tree` — Decision Tree-ის ტრენინგი
- `model-experiment-bagging` — Random Forest-ის ტრენინგი
- `model-experiment-xgboost` — XGBoost-ის ტრენინგი

---

## Feature Engineering

- **ცვლადების ამოღება:** არარელევანტური feature-ები, როგორიც იყო `TransactionID` და ტრანზაქციის დრო (`TransactionDT`), ამოვიღე.
- **გამოტოვებული მნიშვნელობები:** NaN-ები მედიანით შევავსე.

---

## Feature Selection

Feature Selection-ისთვის გამოვიყენე რამდენიმე ძირითადი მიდგომა:

- **კორელაციის ფილტრი:** გავფილტრე ისეთი ცვლადები, რომლებიც ერთმანეთთან მაღალ კორელაციაში იყვნენ. Threshold-ის სხვადასხვა მნიშვნელობა ვცადე, თუმცა შედეგზე დიდად არ იმოქმედა.
- **SHAP Values:** XGBoost-ში გამოვიყენე SHAP Values feature-ების ასარჩევად, რამაც საკმაოდ კარგი შედეგი აჩვენა.
- **NaN Threshold:** გამოვიყენე ზღვარი იმ ცვლადების გადასაყრელად, რომლებსაც ძალიან ბევრი NaN მნიშვნელობა ჰქონდათ.
  - თავდაპირველად ეს მაჩვენებელი `0.7` ავიღე, რამაც ძალიან ბევრი ცვლადი გამიფილტრა, შეამცირა ინფორმაცია და საბოლოოდ უფრო ცუდი მოდელები მივიღე.
  - შემდეგ Threshold ავწიე `0.8 - 0.9` დიაპაზონში, რამაც შედეგები საგრძნობლად გააუმჯობესა.

---

## Training (მოდელების ტრენინგი)

როგორც ზემოთ აღვნიშნე, დავტესტე ოთხი მოდელი. ტრენინგის პროცესში ხშირი პრობლემა იყო ოვერფიტი (Overfitting). ბევრ მოდელს უკეთესი ვალიდაციის შედეგი ჰქონდა, მაგრამ ოვერფიტის გამო საბოლოოდ უფრო სტაბილური მოდელის არჩევა მიწევდა.

### მოდელების შედეგები ტესტ სეტზე

- **Logistic Regression:** `0.82`
- **Decision Tree:** `0.80` *(ყველაზე ცუდი შედეგი აჩვენა)*
- **Random Forest:** `0.87` *(მნიშვნელოვანი გაუმჯობესება წინა მოდელებთან შედარებით)*
- **XGBoost:** `0.88` *(საუკეთესო შედეგი)*

### ჰიპერპარამეტრების ოპტიმიზაცია

ჰიპერპარამეტრების ოპტიმიზაციისთვის გამოვიყენე `GridSearch`.

თავდაპირველად ყველა შესაძლო კომბინაციას ვტესტავდი, თუმცა ეს ძალიან დიდ დროს მოითხოვდა. შემდეგ მიდგომა შევცვალე და შემთხვევითად ვირჩევდი 10 კონფიგურაციას, საიდანაც საუკეთესოს ვიტოვებდი.

### საბოლოო არჩევანი

საბოლოო მოდელად ავიღე **XGBoost**, რადგან მან ყველაზე მაღალი შედეგი აჩვენა.

- **დალოგილი ინფორმაცია:** ჰიპერპარამეტრები, კორელაციის Threshold, NaN Threshold
